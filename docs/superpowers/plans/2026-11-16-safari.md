# Safari in ProMax

Port the Safari feature from huypham691/server at d5382bea into the existing TypeScript gameplay, bitmap renderer, pack and save repository. The branch starts at origin/main. Safari suspends the original room and returns to that room on exit. Its checkpoint lives in optional meta.safari so old saves remain supported.

- [x] Add typed rules, persisted RNG and run state with focused tests for fees, movement, capture, escape, full storage and last-ball ordering.
- [x] Import map and original pixel art through Pack. Add a Safari renderer using the existing bitmap font and sprite adapters.
- [x] Connect menu, touch and keyboard input, pet storage and save checkpoints through GameplayHost.
- [x] Check save validation, reload, TypeScript, build and browser entry flow.

Publish this implementation on branch `safari` in garnalam/VQSV_ProMax.

The original rules charge 20 badges and give 30 balls. Encounters recur after 12–22 tiles. There are eight ordinary species with 90% total weight and five divine species with 10%. Bait and rock alter catch/flee probabilities and cancel each other. The last ball is resolved before leaving. Use the game’s pet factory, collection and bank capacity. All changes to badges, balls and pets use the same game snapshot.

ProMax runs gameplay in the browser. The port uses that existing architecture and save API. Its outcomes have the same client authority as the rest of ProMax gameplay.

Validation completed with 138 focused tests, the TypeScript build and Vite production build. Browser checks cover desktop entry, movement, encounters, bait, exit and IndexedDB writes, plus portrait touchscreen entry and exit. The Vite configuration now accepts a standalone checkout when the optional shared admin module and wiki page are absent.
